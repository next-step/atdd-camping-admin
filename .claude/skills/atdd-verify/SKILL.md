# 4. 판정

`docs/principles.md`, `docs/plan.md`를 먼저 읽는다.

## 입력

- 바뀐 코드
- 쌓인 테스트 전부

## 하는 일

- 바뀐 코드를 읽는다.
- `./gradlew test`(필요하면 `--rerun-tasks`)로 쌓인 테스트를 전부 돌려 회귀를 확인한다.
- 요구사항대로 됐고 원래 되던 것이 안 깨졌는지 판정한다.

## AI에게 주는 지시

- 전체 테스트가 통과하고 요구사항대로 됐다고 판단되면 커밋한다.
- 이번 티켓으로 그린이 된 인수 테스트의 `@Nested` Javadoc이 레드였던 시절 문구
  그대로 남아 있지 않은지 확인하고, 남아 있으면 갱신한다(규칙은 `test-guide.md`).

## 남기는 것

- 커밋
- 처리하며 발견한 것이 있으면 `docs/tickets.md`에 남긴다.

## 통과 조건

요구사항대로 됐고 원래 되던 것이 안 깨졌는지 확인한 뒤에만 `git add`/`git commit`을
실행한다. 이 단계로 티켓 처리가 끝난다.
