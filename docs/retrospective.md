- 경험에서 더한 것: T-2에서 합계만 비교하면 귀속일과 연결 대여의 차이를 놓쳐 식별자별 대조와 후보 값 구분을 ATDD 스킬에 추가했다(커밋 `e84446c`); T-3의 상태 변경 후 별도 조회·세 리포트 검증 규칙은 스킬이 아니라 `test-guide.md`에 추가했다.
- AI가 멈춘 자리에서 판정한 것: `HANDED_OFF`로 인계받았을 때 취소 제외 단언만 실패한 정상 Red라고 판단해 테스트를 유지한 채 구현을 진행하기로 했다; 인계를 테스트 통과로 간주하지 않았다.
- 절차를 알아서 빨라진 것과 덜 판 것: 실제 로그인 JWT, `@Sql` 격리와 Red→구현→독립 판정 절차를 재사용해 인증·데이터 준비 탐색을 줄였고, 다른 예약 상태와 취소 예약에 연결된 대여의 매출 정책은 T-6으로 남겼다.

### 스킬·훅·스크립트 배치

| 어디 | 무엇 | 왜 거기인가 |
|---|---|---|
| 스킬 | 요구 범위, 이유·예시의 타당성, 인수 조건 때문에 실패한 올바른 Red인지 판정 | 내용과 맥락을 판단해야 하므로 형식 검사나 종료 코드만으로 결정할 수 없다. |
| 훅 한 줄 | 각 티켓의 `범위와 이유` 본문과 내용 있는 Given·When·Then 예시의 존재 여부 검사 (`AC_FORMAT`, 경고용 추가 완료·실제 UI 확인 전) | 정해진 형식의 존재 여부로 판정할 수 있고, 턴 사이의 상태를 저장할 필요가 없다. |
| 스크립트 | 전체 테스트 재실행, 실패 이름별·전체 횟수 집계, 한계 인계, 상태 초기화와 이벤트 기록 | 같은 실패인지 구분하고 여러 실행에 걸친 횟수와 이력을 저장해야 한다. |

형식의 존재는 훅이 확인하지만 이유가 타당한지, 예시가 충분한지, 요구사항에 없는 정책을 정해도 되는지는 스킬과 사람이 판단한다. 기존 테스트 스크립트는 유지하고 문서 형식 훅만 별도로 추가했으며, 문서 훅은 아직 차단으로 승격하지 않았다.

### 확인된 증거와 남은 확인

- 실제 Stop 기록에는 `BLOCKED 1/3` → `BLOCKED 2/3` → `HANDED_OFF 3/3`과 이후 턴의 `PASSED`가 남아 있다. 한계 인계는 테스트 통과 기록과 구분한다.
- 다른 실패 이름이 처음에는 1회로 집계되는지, 이름별 3회·전체 5회에 인계되는지, 인계와 통과 후 다음 실패가 다시 1회·종료 코드 2로 차단되는지는 임시 상태·로그·이벤트 파일과 모의 테스트 결과로 검증했다. 이 결과를 실제 Stop 재차단 기록으로 적지는 않는다.
- 새 문서 훅은 격리된 명령 검증 16건, 메모리 문서의 EOF·본문 경계 검증 12건, 현재 저장소의 루트·하위 디렉터리 실행 2건으로 총 30건을 확인했다. 누락 시 경고 JSON과 종료 코드 0, 정상 시 무출력과 종료 코드 0을 확인했으며, 실제 Codex UI 경고 사이클은 아직 확인하지 않았다.
- 남은 확인은 새 문서 훅의 신뢰·활성화 및 실제 경고 관찰, 작성자가 결정할 차단 승격과 복구 실측이다. 기록 파일과 관련 변경의 커밋도 아직 하지 않았으므로 과제 전체 완료로 표시하지 않는다.
