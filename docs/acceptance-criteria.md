# 인수 조건

## T-1 상품 수정이 저장되지 않음

```
규칙   상품 정보를 수정하면 그 변경 내용이 저장되어, 이후 조회 시 변경된 값으로 나와야 한다
이유   운영팀이 재고·가격 등을 수정해도 반영되지 않으면, 화면에 보이는 값과 실제 값이
       어긋나 잘못된 안내(품절 상품을 판매 가능으로 표시 등)로 이어진다

Given  상품(id=1)의 이름이 "랜턴"이다
When   이름을 "랜턴-수정됨"으로 수정해 저장한다    Then  302, 조회 시 "랜턴-수정됨"으로 나와야 하나 실제로는 "랜턴" 그대로 (변경 안 됨)
```

## T-2 매출 리포트 금액이 화면마다 다름

```
규칙   같은 예약의 매출은, 어느 리포트에서 보든 같은 날짜의 매출로 잡혀야 한다
이유   일별 리포트가 어떤 예약을 "그 날" 매출로 집계했는데 개별 항목 내역에서는 같은
       예약이 다른 날짜로 찍히면, 운영팀은 그 예약이 실제로 언제 매출로 반영됐는지
        
        알 수 없고 두 화면 중 어느 쪽을 신뢰해야 할지 판단할 수 없다

Given  예약 #13은 reservationDate=2026-09-13(1박, 예약매출 50000원), createdAt=
       2026-09-03이다(예약일과 예약이 실제로 등록된 시각이 다름)
When   GET /admin/reports/revenue/daily?date=2026-09-13    Then  200,
       totalReservationRevenue=50000 (예약 #13이 이 날 매출로 잡힘)
When   GET /admin/reports/revenue/range?from=2026-09-13&to=2026-09-18    Then  200,
       totalReservationRevenue=50000 (일별 리포트와 총액 일치)
When   GET /admin/reports/revenue/range/entries?from=2026-09-13&to=2026-09-18
       Then  200, 예약 #13 항목의 occurredAt=2026-09-03T20:54:41 — 조회 범위
       (09-13~09-18) 밖의 날짜인데도 이 범위의 결과에 포함되어 나옴

두 리포트의 합계 금액(50000)은 서로 일치한다. 어긋나는 것은 개별 항목 내역에 찍히는
"날짜"다: 일별/기간 리포트는 reservationDate로 필터링·표시하는데
generateRangeRevenueEntries(SalesService.java 146행)는 예약 항목의 날짜로
reservationDate가 아닌 createdAt(r.getCreatedAt())을 쓴다. 그 결과 같은 예약이
일별 리포트가 매출로 잡은 날과 개별 항목 내역에 찍히는 날이 달라지고, 조회 범위
밖의 날짜를 가진 항목이 그 범위의 결과에 나타난다. 총액 비교만으로는 이 결함을
잡아낼 수 없다.
```
