# 테스트 작성 제약

- 보호된 API 인수 테스트는 실제 로그인 응답의 JWT를 Bearer 토큰으로 보내 인증 관문을 통과한다.
- 상품 수정 테스트는 전용 상품 ID를 잡고 각 테스트 전에 `@Sql`로 같은 초기 상태를 다시 만든다.
- 부분 수정 회귀 테스트는 변경 요청에서 다른 필드를 생략하고, 후속 조회로 생략한 필드가 보존되는지 검증한다.
- 매출 리포트 테스트는 합계에 다른 데이터가 섞이지 않도록 `@Sql`로 전용 거래만 준비하고, 예약일·생성일·입실일을 서로 다르게 두어 귀속일로 선택한 필드를 검증한다.
- 예약과 연결된 대여의 귀속일을 검증할 때는 예약일과 대여 생성일을 서로 다르게 두고, 각 날짜의 일별·기간 요약·상세 응답을 함께 확인한다.
- 예약 상태에 따른 매출 포함 여부를 검증할 때는 전용 예약을 `CONFIRMED`로 초기화하고, 상태 변경 응답과 별도 예약 조회로 저장을 확인한 뒤 일별·기간 요약·기간 상세를 모두 조회한다.
